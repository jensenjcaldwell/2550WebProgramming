In this final iteration of your Personal Website, you will incorporate a "Visitor Registration" form. You will utilize Flexbox for the layout and write custom JavaScript to handle event listeners, regular expression (Regex) pattern matching, and real-time DOM manipulation for validation feedback.

I. Refactor & Organization (15 Points)
Clean up your existing codebase to support a growing JavaScript application.

Single-Page Architecture: Ensure your site functions as a Single-Page Application (SPA). The new form must be hidden by default and revealed when a "Log Visit" menu item or button is clicked, matching the behavior of your other sections.

File Structure: Organize your JavaScript into functional modules within a js/ subfolder:

js/main.js: Your primary entry point.

js/validation.js: Your form validation library.

js/page.js: Dedicated logic for page switching and theme toggling.

Documentation: At the top of main.js, include a multi-line comment header that contains a disclaimer stating you wrote the code yourself, followed by a brief summary of the changes and fixes you implemented during this refactor.

II. Visitor Form Validation (70 Points)
1. Form Structure & Layout
Build a visually appealing form using Flexbox. Your <form> tag must include a novalidate attribute to disable HTML5 browser validation. It must also include an inline return false statement: <form id="myform" novalidate onsubmit="return false;">. This prevents the automated grading environment from timing out.

Required Form Elements:

Field	Input Type	Validation Requirement
First & Last Name	Text	Required
Address & City	Text	Required
State	Text	Required. Must validate against the provided stateAbbreviations array.
Zip Code	Text	Required. Must match regex for 5-digit or 9-digit format.
Cell Phone	Text	Required. Must match a valid phone number regex (find one via Regexr or Regex101).
Email Address	Text	Required. Must match the provided email regex.
Discovery Method	Checkbox Group	Required. At least one option (e.g., Google, Friend) must be checked.
Comments	Text Area	Optional
2. JavaScript Validation Library (validation.js)

Complete the stubbed functions in the provided template to build your validation library.

Event Listeners:

onChange: As the user exits a field (tabs out or clicks away), validate that specific element immediately.

onSubmit: Capture the submit event on your form. You must prevent the default submission (ev.preventDefault()) and stop event bubbling. Run validation on the entire form from here.

3. User Feedback & Submission

Provide clean, inline feedback using CSS and DOM manipulation.

Error States: When a field is invalid, use JavaScript to add a .was-validated class to the input. Your CSS should use the input.was-validated:invalid pseudo-class to turn the border red and reveal the error message <div>.

Success States: If a field is valid, indicate success (e.g., a green border).

Submission Handling: Upon clicking Submit (use a standard <button type="submit">), if form.checkValidity() returns true, hide the form entirely and display a "Thank you for logging your visit!" message on the page. If false, display all relevant error messages.

III. Styling & Responsiveness (15 Points)
Flexbox Forms: Use display: flex to align your labels, inputs, and error messages cleanly. Make the ugly template look professional.

Theme Integration: The custom "Theme" you built in Project 4 must apply to this new form section (colors, fonts, input styling).

Tablet/Desktop Responsiveness: Ensure the form does not break or stretch awkwardly on large desktop monitors or medium tablet screens.
